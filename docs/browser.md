# 浏览器

[← 回到 README](../README.md)

没有接口、只能在网页上做的事（"去这个网站查一下我的订单状态"），Agent 用 `browser` 工具。
浏览器有两种放法（`SMRA_BROWSER`）：
- `local`（默认）：宿主上的一个独立进程（Playwright 驱动），配置目录在 `data/browser/profile`，登录态在那里，电脑读不到。
- `docker`（Linux 上建议）：浏览器跑在一个只接内部网络的容器里，网页就算攻破了浏览器，碰到的也只是容器。
  容器上网只能走宿主在这个网络网关上开的一个转发，它只通到出网代理；容器根文件系统只读、非 root、限内存和 CPU。
  容器里不留登录状态：Cookie 和本地存储存在宿主的 `data/browser/state.json`，每次连上时交给浏览器，
  所以容器删掉重建登录也不丢（网站存在 IndexedDB 里的东西不保留）。
  镜像 `smra-browser:<Playwright 版本>` 第一次用时自动构建，要几分钟；也可以先建好：
  `docker build -f browser/Dockerfile --build-arg PLAYWRIGHT_VERSION=<版本> -t smra-browser:<版本> browser`。
  升级 Playwright 后会用新标签重建，旧镜像可以删掉。

要清掉浏览器里所有网站的登录：停掉宿主，删掉 `data/browser/profile`（local）或 `data/browser/state.json`（docker）。
Agent 只有几个动作：打开地址、取无障碍树（可操作的节点带编号）、点击、输入、按键、后退、截图、请你登录。
没有"在页面里执行脚本"，也拿不到 Cookie。

第一次用之前装浏览器（或者用本机已有的 Edge / Chrome：`SMRA_BROWSER_CHANNEL=msedge` 或 `chrome`）：

```bash
uv run playwright install chromium
```

**登录由你来。** Agent 需要登录时发来一个接管页面的链接（默认 `http://127.0.0.1:8790/takeover/...`）。
你在页面上看着浏览器的实时画面点击、输入，密码只经过宿主和浏览器，不经过电脑和模型。登录完点"完成"，Agent 在原对话里接着做。
链接带一个随机钥匙，30 分钟后失效；页面有删除键（长按连删）和后退键，退到头会提示，不会白屏。
接管没完成时 Agent 又要用浏览器，宿主会把链接再发你一遍，这一轮先结束，等你登录完再接着做。
不想登录了，在页面上点取消，或者发 `/new`：新对话会一并结束没完成的接管。
宿主自己写给 Agent 的说明（比如"用户正在接管"）不当成外部内容查提示注入。

要在手机上用，只把这个端口暴露给你自己的设备，并把外部地址填进 `SMRA_TAKEOVER_URL`。我们用的是 Tailscale（只在你的设备组成的私有网络里可见，不开 Funnel）：

```bash
tailscale serve --bg --https=443 http://127.0.0.1:8790
# .env 里：SMRA_TAKEOVER_URL=https://<机器名>.<tailnet>.ts.net
```

**浏览器的流量同样经过出网代理和裁决者**，用浏览器自己的通行证（电脑里没有）。判定看的是浏览器实际发出的请求：

| 浏览器发出的请求 | 判定 |
| --- | --- |
| 打开出现过的地址（页面里的链接、搜索结果、你消息里的） | 放行 |
| 页面加载同站资源；跨站的脚本、样式、图片、字体 | 放行 |
| 页面脚本发往别的网站、地址没出现过的数据请求 | 拦下，不问你 |
| Agent 打开一个没出现过的地址；GET 表单提交了它填的内容 | 问你 |
| Agent 操作引起的提交（POST 等） | 问你，审批里列出表单字段（密码类字段隐藏），并说明是否带着登录态 |
| Agent 没在操作时页面自己发的提交（统计、心跳）；运行结束后浏览器发的任何请求 | 拦下，不问你 |
| 你在接管时的请求 | 放行（是你的操作） |
| 你在这次对话里亲手发过网址的网站上，同站的请求：Agent 打开自己拼的地址、它操作引起的提交、页面自己的后台请求 | 放行，不问你 |

"拦下，不问你"不等于瞒着 Agent：Agent 下一次用浏览器时，结果里会写明拦了哪些同站请求、为什么、页面可能因此不正常，
并叫它别用 fetch、curl 去绕；办不成就停下来告诉你卡在哪，没点名的网站还会请你把网址发来。发往别的网站的只报个数。

最后一行是"你点名的网站"：你发来"去 https://某网站 买个东西"，就是让 Agent 在那个网站上替你办事，每步都问反而办不成——
页面后台的请求被悄悄拦下时，Agent 不知道原因，只会四处乱试。规则的边界：

- 只认你自己打的消息里的网址，搜索结果、网页里的链接、转来的内容都不算；只看这一个对话。
- 只放行发往这个网站本身、且是同站发起的请求（看浏览器填的 `Sec-Fetch-Site`）。发往别的网站的照上面的规则。
- 本次运行里一旦读到疑似注入的内容，这条规则就停用，回到逐个问你。
- 这意味着在你点名的网站上下单、付款不会再问。不想这样，就别在消息里贴网址，让 Agent 自己去找。

**网站档案。** 没点名的网站（比如例行任务里每天去查的那个），提交类请求默认每次问你、只能批"仅这一次"。
Agent 可以用 `profile_propose` 给它提交一份网站档案（`type: site`，不写 `auth`），和服务档案一样由你审阅、确认后才生效：

```yaml
type: site
service: shop                 # 名字不能和已连接的服务重名；一个主机只能属于一份网站档案
title: 小店
hosts: [shop.example]         # 浏览器实际提交到的主机
actions:
  - id: search
    match: {method: POST, path: /api/search}
    class: read               # 用 POST 的查询：以后直接放行
  - id: message
    match: {method: POST, path: "/messages/{to}"}
    class: send
    summary: "给 {to} 发消息"   # {query.名字} 网址参数，{form.名字} 表单字段，{body.名字} JSON 请求体的顶层字段
    show: [form.text]
    constraint_keys: [to]     # 长期授权只覆盖同一个 to
```

- 标成 `read` 的请求直接放行（包括页面脚本自己发的）。审阅里会用 ⚠ 标出被标成读取的 POST 等请求。
- 其余类别：Agent 操作引起的提交照样问你，但审批里多了档案的摘要，并且可以选长期授权；不可撤销、付款、没有约束键的发送只能"仅这一次"。
  页面后台的提交、跨站的脚本提交照旧直接拦下。
- 没匹配到规则的请求照旧按上面的表。读到疑似注入的那次运行里，长期授权照样暂停。

做演示时可以录下浏览器画面：`SMRA_BROWSER_RECORD_DIR=<目录>`。视频在浏览器关掉时才写完，所以要让宿主正常停下（见 [部署与运维](deploy.md) 的"停止"）。
录像里有 Agent 看到的一切，包括你登录时在页面上输入的账号（密码框里是圆点），用完记得删。
