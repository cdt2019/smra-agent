# Agent 什么时候醒、什么时候说话

[← 回到 README](../README.md)

Agent 只在收件箱里有事件时运行。事件有四种来源：你的消息、你对审批的答复、到期的定时器、外部系统的 Webhook。

| | 前台运行 | 后台运行 |
| --- | --- | --- |
| 谁触发 | 你的消息、你的审批答复 | 定时器、Webhook |
| 最后的回复 | 直接发给你 | 不发，只留在记录里 |
| 要告诉你 | 回复就是 | 必须调 `notify`，选 `now` 或 `digest`；不调就是保持安静 |

**定时器**由宿主保存，Agent 通过工具设定，上限由宿主执行：

- 跟进（`follow_up`）：一次性，到时在设定它的那个会话里叫醒 Agent。最早 1 分钟后。
- 日程（`schedule`）：按 cron（本地时间）重复，每次开新会话。最多每 15 分钟一次。Agent 每设一个日程，你都会收到一条提醒。
  设 `same_session=true` 的日程每次接着同一个会话（能看到上几次的对话）；一个会话接满 `SMRA_SCHEDULE_SESSION_FIRES`
  次（默认 10）就换新的，免得上下文越积越长。
- `/run <定时器号>`：让日程现在就做一次，不做前置检查，下一次时间不变。`/timers` 在每个定时器下面列最近 3 次的结果
  （发了消息、没打扰你、前置检查说没变化……），并列出最近取消的日程；`/resume <定时器号>` 重新打开，从现在往后算下一次。
  夜间整理被你取消后也可以这样恢复。
- 前置检查：日程可以带一个脚本，调度器到期时先在电脑里跑它，不经过模型。退出码 10 表示"没变化"，这次到期就此结束、不产生运行。
  脚本拿到的通行证只能出网，调不了模型，也碰不到宿主接口；需要批准的请求直接被拒，不会打扰你。
- 宿主停机后重启：错过的跟进全部补上，错过的日程每个只补一次。
- 夜间整理：内置日程，默认每天 3:30。整理前先给主目录做快照。过去一天没有任何活动就不叫醒 Agent。

Webhook 的配置见 [接入外部服务](integrations.md#webhook)。

**发件节奏**（只能在 `.env` 里改，Agent 改不了）：

| 类型 | 送达 |
| --- | --- |
| 回复 | 立刻 |
| 即时通知（`now`） | 立刻，带"有用 / 没必要"按钮。每天默认 3 条，超出的降为摘要；安静时段（默认 23:00–08:00）延后 |
| 摘要（`digest`） | 攒到摘要时间（默认 8:00），合成一条 |
| 审批 | 立刻，不受上限和安静时段约束 |
| 系统提醒（注入警告、新日程、后台任务失败） | 不受上限约束；安静时段延后 |

发送失败按退避重试，5 次后放弃。最近发出的通知和你的打分会出现在 Agent 的 `<memory>` 里，避免重复说、也让它知道哪类通知你嫌多。

## 多角色

一个角色是一份角色说明加一套自己的记忆。在 `data/core/roles/` 下放 `<名字>.md`（名字用小写字母），和 `AGENT.md` 一样只有你能改：

```markdown
---
title: 研究员
description: 查资料、读网页，把结论写成文件
---
只写有出处的结论。
```

- **点名**：消息开头写 `@researcher` 或 `@研究员`。没点名的交给默认角色（协调者，`SMRA_DEFAULT_ROLE`，默认 `coordinator`；
  它也可以有自己的文件）。每个角色有自己的对话。`/roles` 列出角色。非默认角色发来的消息，开头由宿主标上【研究员】。
- **记忆各自一套**：默认角色用 `memory/`，其他角色用 `roles/<名字>/memory/`。技能、工具、`work/`、账号连接、授权都共用。
- **交接**：角色用 `handoff(role, task)` 把任务交给另一个角色，收件箱里多一条事件，目标角色在自己的新会话里处理，
  只看得到 task，看不到原来的对话。源头是你的消息时，接手的角色直接回复你；源头是定时器之类的后台事件时，照样只能 `notify`。
  只有一个工作进程，角色轮流干活，不会同时改同一个文件。
- **两个上限**：一条消息引发的交接最多 5 跳（`SMRA_HANDOFF_MAX_HOPS`）；一个任务连同它引发的所有交接，
  总花费不超过 60 万 token（`SMRA_TASK_TOKEN_BUDGET`）。到了上限，交接被拒绝、模型调用被拒绝，并告诉你一次。
- **角色不是安全边界**（设计文档 17.3）：它们共用一台电脑和一套授权，一个角色读得到另一个角色的记忆目录。分开只是为了上下文和专注。
- 只有默认角色、没有别的角色文件时，系统提示词里没有角色一节，行为和第 7 步一样。

## "发不发"评测

`evals/notify_cases.yaml` 里有 27 个用例：一个事件加当时的背景，标注期望结果是即时、摘要还是安静。
运行脚本用和真实运行相同的系统提示词、工具和消息顺序调模型：

```bash
uv run python evals/notify_eval.py
```

它会调用真实模型，要花钱（每个用例通常 1–3 次请求）。输出准确率、"该安静时安静"的比例、"该马上说时说了"的比例、
以及即时通知里不该打扰的比例，结果存到 `evals/results/`。改了系统提示词或换了模型后跑一遍。
